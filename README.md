# 续聊 · GPT网页版自动会话插件

**0.3.2，Chromium Manifest V3 开发者模式安装版。** 使用浏览器中已登录的 ChatGPT 网页，自动选择话题、输入、发送、等待完整回复并续聊。支持中文、英文和日文界面，不需要 API Key 或服务器。


## 快速开始
0. 用途：基于 GPT 账号被风控、降智后可通过持续使用网页版对话来恢复状态的特性而开发的自动化 chat 插件
0. 准备工作：在使用插件前，先到gpt 的设置-账户安全与登录中，退出 codex cli 连接与所有已登录账号，静置至少 24 小时后重新登录再使用插件

1. 在 [Releases 页面](https://github.com/ititrica/chrome-xuliao/releases/latest)下载最新的 `xuliao-0.3.2-Chromium.zip`，解压到一个准备长期保留的文件夹。
2. 在 Chrome、Edge 或其他兼容 Chromium 浏览器中打开扩展管理页（Chrome 为 `chrome://extensions/`，Edge 为 `edge://extensions/`），开启开发者模式。
3. 选择“加载已解压的扩展程序”，选择解压后**直接包含 `manifest.json` 的 `xuliao-extension` 文件夹**。以后更新扩展时，替换该目录中的文件，再在扩展管理页点击“重新加载”。
4. 在同一浏览器中登录 [ChatGPT](https://chatgpt.com/)。点击浏览器工具栏中的续聊图标，打开页面悬浮菜单，再点击“打开控制台”；也可以从扩展管理页打开扩展选项页。
5. 在“运行任务”中设置会话数量、并发、图片组比例和提示词抖动范围，点击“随机抽取并开始”。插件会在浏览器内打开新对话，逐轮输入并等待回复；可切换到其他应用工作，保持浏览器运行即可。
6. 在控制台或悬浮菜单中可暂停、继续或停止；一组结束后任务页会关闭，可以从控制台重新打开已保存的会话。需要保存记录时，在开始下一批之前点击“导出对话记录”。

默认每批 6 组，轮间等待 12–45 秒，文字与图片回复最长各等待 1200 秒；逐字输入、图片创作和提示词抖动默认开启。网页登录和验证由用户完成，图片生成取决于账号及当前模型是否支持。

## 使用聊天库和词库

- 在“聊天库”搜索、浏览或编辑连续会话，支持新建、导入和导出；点击某组的“预览抖动”可查看抽样后的全部轮次。
- 在“抖动词库”按分类搜索并导出词库。运行任务页可以分别启用主题侧重、场景与词语、数字和语气抖动；语气分为礼貌、普通、随意、不太礼貌，每组会话随机选择一种，组内所有轮次保持一致；悬浮菜单提供总开关。
- 图片会话首轮请求生成图片，后续轮次继续修改上一张图。可用图片比例滑块选择本批图片会话所占比例。

## 会话与图片比例

- 内置 380 组关联会话：280 组文字主题各 15 轮、100 组图片主题各 20 轮，共 6,200 条提示词，涵盖 15 类主题。
- 文字随机运行 6–15 轮，图片随机运行 12–20 轮。始终从第一轮开始并按顺序连续进行，没有手动轮数选项。
- 图片首轮直接用文字请求生图，之后每轮基于上一张图修改并输出新图，持续优化主体、构图、光线、材质与细节。
- 默认运行 6 组，最多 300 组。图片创作和逐步输入默认开启，轮间随机等待 12–45 秒。
- 横向图片比例滑块范围 0–100%，默认 30%。按本批会话组数四舍五入，默认 6 组为图片 2 组、文字 4 组。比例指组数，图片会话包含更多轮次。主题库存不足时自动用另一类补足，并显示预计数量；关闭图片开关后只抽文字。
- 并发关闭时依次进行；开启后每批随机选择 1–3 个同时运行的名额，结束或跳过后补位。每批不会重复抽取同一脚本。
- 插件优先处理任务页：已有草稿自动清空，输入被修改或焦点变化时重新定位和输入；额外手动消息不会中止任务，也不会被计入插件回复。

## 安装与更新

1. 使用 Chrome 120+、Edge 120+ 或支持 Manifest V3 和 chrome.debugger 的 Chromium 浏览器。
2. 解压安装包，找到包含 manifest.json 的 xuliao-extension 文件夹。保留此目录，浏览器会持续读取其中的文件。
3. 打开 chrome://extensions/（Edge 为 edge://extensions/），开启开发者模式，选择“加载已解压的扩展程序”。
4. 在同一浏览器配置中登录 https://chatgpt.com/。生图需要账号和网页模型支持图片生成。
5. 点击工具栏插件图标打开悬浮菜单，或进入扩展选项页使用完整控制台。

已有安装：替换原安装目录，在扩展管理页点击“重新加载”，刷新控制台和任务页。0.2.0 起使用 debugger 权限，运行时可能显示“续聊正在调试此浏览器”。用户主动取消连接时插件暂停批次。

升级合并新增 80 组图片脚本，并将未修改的旧图片脚本升级为 20 轮连续改图。通过已发布内容的摘要识别原版，保护自定义和编辑过的脚本。旧默认参数迁移到新值，自定义数值保留。新规则用于新批次，正在运行的任务继续使用启动快照。

## 浏览器内切页与原生设备输入

新会话在任务浏览器内选中，输入框稳定至少两秒后才开始；并发时新页面逐个完成就绪确认。输入和点击只切换该浏览器内的任务标签页，通过 Chromium 调试协议和页面焦点模拟发送原生设备事件，不调用窗口聚焦，不把其他应用挤出全局前台。并发可同时等待多个回复，设备输入事务串行执行。

这属于“只占用任务浏览器内的标签页”：你可以在其他应用工作，但任务输入时仍会切换任务浏览器的标签页。建议使用单独的浏览器窗口或配置文件运行。最小化窗口、系统休眠或浏览器主动冻结页面可能影响执行速度；当前不保证这些情况下实时运行。点击“打开控制台”或“查看页面”属于用户主动操作，会照常显示对应窗口。

聊天网页的点击、清空、逐字输入、换行、发送、停止生成、重试和回到底部，全部使用浏览器原生鼠标、键盘和输入法事件。适配器只观察 DOM，不通过 value 赋值、execCommand 或合成 JavaScript input 事件操作网页。

逐步输入每次一个字符，基础间隔 140–360 毫秒，标点额外停顿 280–730 毫秒，偶尔加入更长的短暂停顿。关闭逐步输入后仍使用设备事件。每次事件核对任务状态，暂停或停止后不启动新的输入。

整组会话完成或自动跳过后，先保存记录并关闭该任务页，再在浏览器内打开下一组。最后一组完成也关闭任务页，可通过控制台“打开已保存会话”重新查看。只关闭当前批次创建的任务页，不删除聊天历史。关闭失败自动重试，成功后再补位。

等待回复期间及完成后，若“回到底部”下箭头可见，会通过原生鼠标点击以显示最新回复。

## 回复判定与自动恢复

文字和图片默认最长等待均为 1200 秒。有完成标记时，内容稳定约 3.5 秒后确认；缺少标记时，需要输入框可用、没有实际生成信号、内容稳定至少 10 秒。实际生成中的停止按钮或流式标记仍会阻止提前完成。图片轮次还需出现加载成功的图片。

普通错误自动恢复：

1. 核对提示词是否已出现在网页上；已出现则继续等待该条回复。
2. 未出现时清空输入框、重新输入发送；按钮缺失时尝试原生 Enter。
3. 单轮失败后等待 2、5、10 秒重试，第二次输入恢复可刷新网页；成功回复后清零本轮重试次数。
4. 三次重试仍失败，跳过本组，保留记录与原因并继续后续会话。

回复超时或图片未出现时，自动点击可用的重试按钮或延长等待；持续失败则跳过。标签页关闭或离开 ChatGPT 也会自动跳过。登录和验证码需用户完成。

插件按匹配的用户消息限定回复区间，后续手动生成不会阻塞已结束的插件回复。网页没有服务器级消息事务 ID，极端延迟下积极重发仍可能重复。停止按钮可结束批次；浏览器整体重启后任务暂停。

## 控制台、聊天库与记录

悬浮菜单提供会话数量、并发开关、图片组比例、提示词抖动开关、进度、开始、暂停/继续、停止及控制台入口，可拖动、收起和关闭。关闭菜单或控制台不会停止任务。暂停阻止后续输入，已发送的回复仍可记录。

控制台可设置间隔（2–300 秒）、图片比例、逐步输入、图片开关、主题、等待上限和页面选择器。参数对下一批生效。

聊天库支持搜索、编辑、新建、删除、导入与导出。每组可保存 1–20 轮；文字运行至少 6 轮，图片至少 12 轮。JSON 支持会话数组或包含 version:3、conversations 的对象；会话包含 id、title、category、turns，每轮包含 text 和 kind（text 或 image）。

记录可导出提示词、回复、图片链接、恢复次数与失败原因。开始新批次会替换控制台旧批次，重要记录请先导出。图片链接可能过期，需在原网页保存图片。

## 分类词库与提示词抖动

提示词抖动默认开启，分别支持主题侧重、场景与词语、数字和语气四个范围；语气在每组会话开始时抽取一次，后续轮次复用同一语气，下一组重新随机抽取。全部取消时只保留轻量的普通语气衔接，关闭总开关则发送聊天库原文。侧栏“抖动词库”提供 **66 类、3,236 个不同词语与自然短语**（按分类计 3,246 条）；非数字词语独立去重后也超过 2,000 个。

每组启动时抽取一次主题侧重、最多三个匹配词语及带单位的数字。整组重复设定同步替换，后续改图沿用同一角色与风格；重试和恢复使用固定的实际文本。数字通常在原值约 ±25% 范围内变化，小数值允许相邻整数。代码、网址、引用原文、JSON、序号、日期和范围保留；首轮“一张图片”保持不变。

词库支持分类搜索和导出 JSON；聊天库每组有“预览抖动”和“再抽一次”，本地展示替换对照与全部轮次，不请求 AI。正式启动重新抽样。导出记录同时保留原文、发送文本及整组映射。词库为 data/jitter-lexicon.json，运行模块为同内容的 data/jitter-lexicon.js，抖动逻辑在 lib/prompt-jitter.js。维护 scripts/generate-lexicon.py 后运行可同时生成两个数据文件。复杂自定义脚本可先预览或单独关闭场景/数字抖动，详见 docs/JITTER.md。

## 数据、权限与开发

配置、聊天库、批次和检查点保存在 chrome.storage.local，不跨设备同步。没有第三方统计、上传接口或额外 AI API 请求。HTTP 工作台仅为预览，不操作 ChatGPT。

权限为 storage、unlimitedStorage、alarms、activeTab、scripting、debugger 及两个 ChatGPT 域名。设备输入只接受扩展分配的任务页，核对域名、批次、轮次、状态和恢复版本。

```sh
npm ci
npm test
npm run check
npm run package
```

模块：background.js 负责调度和恢复；lib/core.js 负责配置与抽样；lib/device-input.js 负责设备输入；content/adapter-chatgpt.js 观察网页；content/runner.js 执行单页；content/overlay.js 提供悬浮菜单。接入约定见 docs/ADAPTER.md，验证范围见 docs/VALIDATION.md。安装包不含开发依赖、测试数据或私有浏览器回执。

### 0.3.2 回复进度

等待期间约每 1.2 秒重新采样，悬浮窗和控制台同步显示“AI 正在思考”“正在生成回复”“正在加载图片”“正在确认完成”，附已等待秒数、等待上限和已收到字数。无正文且页面仍在生成时归类为思考阶段；这不代表读取了模型内部推理。完成标记出现后稳定约 3.5 秒即可续聊；缺少完成标记时使用约 10 秒的空闲稳定观察。1200 秒是超时上限，不是固定等待时长。
